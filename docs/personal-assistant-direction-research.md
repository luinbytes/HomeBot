# HomeBot personal-assistant direction: Grok Bot and Hermes Agent

Research date: 2026-08-24. External claims below use only first-party xAI or Nous Research sources. HomeBot context comes from the existing repository docs linked in the table.

## Bottom line

HomeBot already has the durable Bot, Bot-owned routine, group handoff, provider-neutral skill, MCP, server approval, and native attention primitives needed for a personal assistant. Its intended shape is closest to Grok Bot at the product level (named teammates that own work) and to Hermes Agent at the self-hosted integration level (skills, MCP, profiles, cron, memory, and many delivery surfaces). The clearest remaining product decisions are first-class skill/connector discovery, memory controls, brief/continuation UX, and whether delivery should remain native-only or become gateway-based.

## Comparison

| Focus | Grok Bot | Hermes Agent | HomeBot implication |
| --- | --- | --- | --- |
| Marketplace and skill installation | Bot skills are reusable instructions available across Bots; private skills can be enabled per Bot. Settings → Plugins exposes Marketplace/Yours for packaged skills and connectors; `/` references a skill and `@` references Bots, groups, routines, and connectors. Teach a task creates a reviewable draft skill. ([skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations), [settings and notifications](https://docs.x.ai/grok-bot/settings-and-notifications)) | Bundled and optional skills live under the Hermes profile; the Skills Hub can browse, search, inspect, install, update, audit, and uninstall skills from official, GitHub, URL, and community sources. Installed skills become slash commands. Plugins can bundle namespaced skills and are opt-in by default. ([Skills System](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/), [working with skills](https://hermes-agent.nousresearch.com/docs/guides/work-with-skills), [plugins](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins)) | HomeBot has versioned provider-neutral Skills, per-Bot assignment, import/export, and safe tool references, but the inspected docs do not define a catalog/marketplace, install preview, provenance scan, or update flow. ([Skills](skills.md), [Plugins and MCP](plugins.md)) |
| Workflow and routine scheduling | A routine belongs to one Bot and runs on a schedule or supported event; it can be tested, paused, edited, and reviewed in Bot details. Background routines run while the laptop is closed, with a 50-routine-per-Bot limit and 20 recent run records. ([skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)) | Cron supports one-shot/recurring natural-language or cron schedules, attached skills, pause/resume/edit/run/remove, fresh agent sessions, and no-agent scripts. Delivery can target the origin chat, files, a platform, or another local profile's Bot Chat. ([Scheduled Tasks](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron/)) | HomeBot is stronger on durable execution semantics: immutable routine versions, dry run, headless daily/interval/webhook/event triggers, durable jobs, overlap/misfire policy, cancellation, and run history. ([Routines](routines.md)) |
| Morning, daily, and weekly briefs | xAI presents daily briefing and morning briefing roles, weekly summaries, and weekday 8:00 AM routine examples; the brief is ordinary Bot work rather than a separate data type. ([Grok Bot use cases](https://x.ai/bot/use-cases), [skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations), [get started](https://docs.x.ai/grok-bot/get-started)) | A morning brief can be created in natural language, combine multiple skills, and deliver to a chosen channel. Cron deliveries are fire-and-forget by default, with an opt-in continuable/threaded mode for follow-up. ([Scheduled Tasks](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron/)) | HomeBot can express these as routines, but the existing docs do not define a named Brief template, source aggregation contract, or continuation surface. Keep the routine engine generic; add a brief UX only when a distinct user workflow is accepted. ([Routines](routines.md), [desktop settings and notifications](desktop-settings.md)) |
| Bot assignment and coordination | A Bot is a durable named teammate with a job, conversation, tools, approval boundary, and recurring schedule. Users create 2–6-Bot groups and direct work with `@`; all Bots share one account cloud computer, so Bot identity is not a security boundary. ([create and manage Bots](https://docs.x.ai/grok-bot/bots), [message and collaborate](https://docs.x.ai/grok-bot/chat-and-collaboration), [approvals, security, and privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy)) | Desktop Bot Mode presents each Hermes profile as a bot with its own Bot Chat and routines; each profile has its own config, memory, sessions, skills, cron jobs, and gateway state. Cron can deliver into the current or another local profile's Bot Chat. ([desktop app](https://hermes-agent.nousresearch.com/docs/user-guide/desktop), [profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles), [Scheduled Tasks](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron/)) | HomeBot deliberately separates durable Bot identity from provider profile, supports per-Bot Skill/plugin assignment, and makes group ownership/handoffs explicit and bounded. This is the right security posture to retain. ([Bots](bots.md), [group chats](group-chats.md), [Skills](skills.md)) |
| Connectors and plugins | Bot connectors are installed from Marketplace, may require browser authentication, and expose individually toggleable tools. Teams inherit Cursor plugin/MCP policy and can restrict servers or member-added servers. ([settings and notifications](https://docs.x.ai/grok-bot/settings-and-notifications), [teams and enterprises](https://docs.x.ai/grok-bot/teams-and-enterprises)) | MCP connects local stdio or remote HTTP servers with startup discovery and per-server tool filtering. Python plugins add tools, hooks, slash/CLI commands, platforms, skills, and memory/provider backends; general plugins are discovered but disabled until explicitly enabled. ([MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp), [plugins](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins), [toolsets](https://hermes-agent.nousresearch.com/docs/reference/toolsets-reference)) | HomeBot's server-owned local MCP registry, per-Bot assignment, cleared environment, bounded process lifecycle, opaque secret references, and untrusted-output boundary are a sound minimal core. Hosted/OAuth connectors remain an adapter decision, not a client shortcut. ([Plugins and MCP](plugins.md), [security](security.md)) |
| Memory | Bot docs promise retained working preferences, facts, and summaries, while copied Bots do not inherit learned memory. The Bot pages reviewed do not specify a bounded memory store, editor, or write-approval workflow. ([create and manage Bots](https://docs.x.ai/grok-bot/bots)) | Hermes has bounded per-profile `MEMORY.md` and `USER.md`, injected as a session-start snapshot; the desktop exposes a Memory Graph with edit/delete, and external memory providers are supported. ([Persistent Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/), [desktop app](https://hermes-agent.nousresearch.com/docs/user-guide/desktop)) | HomeBot's parity contract says app-owned memory survives provider reset, but the inspected docs do not define its storage, editing, bounds, or approval UX. This is the largest personal-assistant semantics gap. ([parity matrix](parity-matrix.md), [working context](working-context.md)) |
| Notifications and delivery | Bot settings can send OS/mobile notifications when a Bot finishes or needs input; focus suppresses notifications while sidebar/dock badges retain unread state. Group chats lack the same per-Bot switch, and mobile push is still rollout-dependent. ([settings and notifications](https://docs.x.ai/grok-bot/settings-and-notifications)) | The gateway delivers through configured messaging channels and cron targets. Responses have an at-least-once delivery ledger; cron can fan out, enter Bot Chat, or become a continuable thread. ([Messaging Gateway](https://hermes-agent.nousresearch.com/docs/user-guide/messaging), [Scheduled Tasks](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron/)) | HomeBot has a precise native macOS/Linux contract for completed work, approvals, failures, focus suppression, and deep links, but no documented multi-channel gateway. ([desktop settings and notifications](desktop-settings.md)) |
| Permissions and approvals | Review shows the proposed action and inputs; Allow once/Deny and narrow Auto Review rules are available, with Require Approval taking precedence. Local-computer execution defaults to Ask every time; secrets and MFA use user takeover. ([approvals, security, and privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy)) | Dangerous commands use smart/manual/off modes; headless cron defaults to deny on dangerous-command approval. Allowlists and DM pairing authorize messaging users, while file safety, isolation, MCP filtering, and injection scanning add layers. ([Security](https://hermes-agent.nousresearch.com/docs/user-guide/security/)) | HomeBot's server policy, `ask-before-changes` Bot default, explicit routine approval steps, plugin read/write checks, and fail-safe unattended jobs match the strongest common denominator. ([Bots](bots.md), [Routines](routines.md), [Plugins and MCP](plugins.md), [activity surfaces](activity-surfaces.md)) |
| User-facing UX | Chat-first teammate UX spans desktop/iOS, with a Bot sidebar, one thread, inline tool/computer/activity records, `/` skills, `@` routing, group chats, and direct redirection while work is running. ([message and collaborate](https://docs.x.ai/grok-bot/chat-and-collaboration), [get started](https://docs.x.ai/grok-bot/get-started)) | Chat-first desktop, CLI/TUI, dashboard, and gateway share sessions; the desktop adds live tool activity, queue editing, management panes, and a Bot roster with profiles and routines. ([desktop app](https://hermes-agent.nousresearch.com/docs/user-guide/desktop), [Messaging Gateway](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)) | HomeBot already projects the same server-owned state to native desktop and Android, with durable activity, approval, unread, and attention surfaces. The missing choice is delivery breadth, not another client-specific authority. ([README](../README.md), [activity surfaces](activity-surfaces.md), [desktop settings and notifications](desktop-settings.md)) |

## Direction for HomeBot

- Preserve the current seam: HomeBot owns Bot identity, history, routines, skills, permissions, and delivery state; providers and plugins remain replaceable capability sources. That is safer and more portable than Grok Bot's shared-computer model. ([Bots](bots.md), [providers](providers.md), [Plugins and MCP](plugins.md))
- If marketplace work is added, copy the user journey rather than either product's trust assumptions: browse → inspect contents and required access → install/enable per Bot → authenticate separately → test safely → update/revoke. Hermes's security scan/opt-in model and xAI's per-Bot enablement are the useful references. ([working with skills](https://hermes-agent.nousresearch.com/docs/guides/work-with-skills), [plugins](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins), [skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations))
- Treat memory as a product contract before expanding it: define scope (owner/Bot/profile), bounded storage, edit/delete, stale-fact correction, and optional write approval. Hermes documents these controls more concretely than the Grok Bot pages reviewed. ([Persistent Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/), [configuration](https://hermes-agent.nousresearch.com/docs/user-guide/configuration))
- Keep briefs as ordinary versioned routines until a first-class Brief object earns its keep; make delivery and continuation explicit when an external channel is added. HomeBot's existing durable job/run model already covers the hard reliability part. ([Routines](routines.md), [Scheduled Tasks](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron/))
